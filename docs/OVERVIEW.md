# 猎场系统 V7.0「Genesis」— 系统功能与运行逻辑概述

> 当前接入说明：V7 启动路径已改为 Tushare MCP 主数据源，腾讯/新浪备用；原规则决策加 DeepSeek 受限复核。本文原有架构描述中的腾讯主源、旧磁盘路径和训练模型集成属于早期说明；当前运行方式以 [部署与操作手册](DEPLOYMENT.md) 和 `core/v7_launcher.py` 为准。


> 一个 **AI 原生、事件驱动** 的 A 股小市值量化交易系统。
> 目标市场：A 股小盘股（总市值 ≤ 50 亿）；资金规模：200 万；运行方式：模拟盘（paper）为主，预留实盘接口。

---

## 1. 系统定位

| 维度 | 说明 |
|---|---|
| 目标品种 | A 股小市值（10~50 亿）为主，预留可转债（T+0）/ ETF / 港股通 |
| 资金结构 | 200 万，分散到 3 个独立账户并行运行 |
| 决策方式 | 信号扫描 → AI 集成评分 → 十二层防线 → 仓位计算 → 订单执行 |
| 风控 | 五层递进熔断 + 止损/止盈 + 持仓监控 + T+1 保护 |
| 自进化 | 每日复盘 → 周度参数优化 → 月度策略晋升/淘汰 |
| 技术栈 | Python 3.12 · asyncio 事件驱动 · FastAPI · SQLite · ECharts |

## 2. 核心架构

```
                     ┌─────────────────────────────────────────────┐
                     │            DataGateway（多数据源门面）         │
                     │  腾讯(主) · 新浪(股票列表/市值/交易日历)         │
                     └──────────────────┬──────────────────────────┘
                                        ↓
                     ┌──────────────────┴──────────────────────────┐
                     │        信号扫描器（signals/）                  │
                     │  技术面 · 资金面 · 情绪面 · AI 异常检测          │
                     └──────────────────┬──────────────────────────┘
                                        ↓ 融合 (SignalFusion)
                     ┌──────────────────┴──────────────────────────┐
                     │         AI 集成（ai/ensemble）                │
                     │  XGBoost评分 · LSTM预测 · PPO仓位 ·           │
                     │  CatBoost风控 · LLM宏观 · (无模型时规则降级)     │
                     └──────────────────┬──────────────────────────┘
                                        ↓
                     ┌──────────────────┴──────────────────────────┐
                     │        决策校验（decision/）                   │
                     │  十二层买入防线 → 仓位计算 → 订单生成            │
                     └──────────────────┬──────────────────────────┘
                                        ↓
                     ┌──────────────────┴──────────────────────────┐
                     │        风控闸门（risk/）                       │
                     │  五层熔断 · 止损止盈 · 持仓/集中度监控           │
                     └──────────────────┬──────────────────────────┘
                                        ↓
                              EventBus（发布/订阅总线，贯穿全系统）
                                        ↓
                     ┌─────────────────────────────────────────────┐
                     │   进化生命周期（evolution/）：复盘→优化→晋升/淘汰   │
                     └─────────────────────────────────────────────┘
```

**两条主线**：
1. **交易主线**：数据 → 信号 → AI 评分 → 校验 → 仓位 → 订单 → 风控 → 执行。
2. **进化主线**：每日/每周/每月复盘交易结果，反馈调整策略参数与信号权重，形成闭环。

## 3. 账户体系（多账户并行）

系统启动时创建/加载 **3 个独立账户**，各自拥有独立的资金、策略参数、风控组件和持仓，共享同一套数据库与事件总线：

| 账户 | 名称 | 资金 | 策略倾向 |
|---|---|---|---|
| `aggressive` | 进攻型 | 70 万 | 高评分、激进仓位 |
| `conservative` | 稳定型 | 70 万 | 稳健、低回撤 |
| `growth_hunter` | 成长猎手 | 60 万 | 成长股聚焦 |

每个账户对应一套独立组件：`AutoTradingEngine`（决策）、`CircuitBreaker`（熔断）、`StopLossMonitor`（止损）、`PositionMonitor`（持仓监控）、`SignalFusion`（信号权重）、`ModelEnsemble`（AI 评分）。

---

## 4. 数据链路

- **主数据源**：腾讯免费 HTTP API（实时行情 + 日 K 线 + 指数），零认证零成本。
- **辅助数据源**：新浪财经（全量 A 股列表 + 总市值 + 交易日历）。
- **可选**：Tushare Pro（需 Token）、AkShare（免费备选）——当前环境未安装，按需启用。
- **存储**：SQLite（`F:/hunting_ground_data/hunting_ground.db`），表结构覆盖 K 线、信号、成交、持仓、熔断日志、策略生命周期、新闻情绪、组合快照、市场报告等。

### 交易日历

- 直连新浪交易日历接口（`klc_td_sh.txt`），**纯 Python 解码**（无 akshare/py_mini_racer 依赖），返回 1990-12-19 至今全量交易日。
- 每日自动刷新；接口不可用时回退到本地硬编码节假日 + 周末判断。
- `Scheduler.is_trading_session()` 据此判断「周末 + 法定节假日」一律休市（A 股不设调休补班）。

## 5. 信号扫描

扫描器在候选池（按市值 10~50 亿筛选出的小市值股票，约 1800+ 只）上运行，产出带评分的信号：

| 扫描器 | 模块 | 产出的信号示例 |
|---|---|---|
| 技术面 | `signals/technical.py` | RSI 超卖、MACD 金叉、布林下轨反弹、V 型反转、底分型 |
| 资金面 | `signals/fund_flow.py` | 量比异动、北向资金流入 |
| 情绪面 | `signals/sentiment.py` | NLP 情绪 / 恐慌贪婪 |
| 异常检测 | `signals/anomaly.py` | AI 异常波动 |

各信号经 `SignalFusion` 按权重融合，得到每只股票的 **综合评分（total_score）**；融合信号池持久化到 `stock_pool` 表，供面板展示（A 级 ≥12 / B 级 ≥8 / C 级）。

---

## 6. 决策引擎（交易周期）

`AutoTradingEngine.run_cycle()` 是单次决策的核心，流程如下：

1. **熔断前置检查**：若五层熔断中「禁止新开仓」生效，则跳过买入，只处理平仓。
2. **信号融合**：取 top 50 个融合信号（最低 5 分）。
3. **逐信号评估**（每次最多 10 个）：
   - 跳过已持仓、以及 L2 禁买名单中的股票。
   - **AI 集成评分**：`ModelEnsemble.decide()` 综合 XGBoost/LSTM/PPO/CatBoost 输出动作、评分、建议仓位、置信度与止损位（无 AI 模型时降级为规则评分）。
   - **十二层买入防线**：`SignalValidator.validate()` 逐层校验，任一不通过即拒绝。
   - **仓位计算**：`PositionSizer` 用类 Kelly 公式，综合评分、波动率、现金预留、最大持仓数、单票上限，算出股数与仓位比例。
   - **换仓**：持仓已满时，比较新信号与末位持仓评分，决定是否「替换卖出」。
4. **止盈止损检查**：遍历持仓，触发硬止损（默认 -5%）或止盈（默认 +20%）则生成卖出订单；T+1 保护（当日买入次日才可触发）。
5. **输出订单**：由 `_execute_order` 落库并更新账户现金/市值/盈亏。

### 十二层买入防线

| 层 | 名称 | 拦截对象 |
|---|---|---|
| L1 | 市值 | 非 10~50 亿小市值 |
| L2 | 数据完整性 | K 线/换手/量比等字段缺失 |
| L3 | 假数据检测 | 异常价格/成交量 |
| L4 | 涨停过滤 | 已涨停无法买入 |
| L5 | 评分阈值 | 综合评分不足 |
| L6 | 情绪 | 市场情绪极差 |
| L7 | 新闻 NLP | 负面舆情 |
| L8 | 黑名单 | 被拉黑股票 |
| L9 | 量价异常 | 放量异常 |
| L10 | 创新低 | 价格创新低 |
| L11 | AI 风险 | CatBoost 风险概率过高 |
| L12 | 流动性 | 日均成交额 < 2000 万 |

---

## 7. 风控体系

### 五层递进熔断

| 层级 | 触发条件 | 动作 | 冷却 |
|---|---|---|---|
| L1 | 单股跌幅 -5% | 平仓该股 | — |
| L2 | 单股当日 -3% | 该股禁买 1 天 | 86400s |
| L3 | 组合当日 -4% | 禁止新开仓 | 86400s |
| L4 | 组合当周 -8% | 全部平仓 + 停摆一周 | 604800s |
| L5 | 沪深300 跌 -5% 或 100+ 跌停 | 全部平仓 + 暂停 | 86400s（不自动恢复） |

每层独立触发、记录到 `circuit_breaker_log`，面板可实时查看触发状态、冷却倒计时、禁买名单与历史。

### 其他风控

- **止损/止盈**：硬止损、移动止损、止盈位（参数在 `config/risk.yaml`）。
- **持仓监控**：集中度、敞口、最大持仓数限制（默认 6 只）。
- **T+1 保护**：当日买入不可当日卖出，避免违规。

## 8. 执行层（预留）

`execution/` 目录实现了算法执行的完整链路（当前模拟盘直接撮合，实盘可切换）：
`algo_executor`（算法执行）、`liquidity`（流动性）、`order_splitter`（订单拆分）、`slippage`（滑点）、`timing`（择时）。

---

## 9. 自进化闭环

| 频率 | 模块 | 动作 |
|---|---|---|
| 每日（15:30 盘后） | `daily_review` | 复盘当日所有交易 |
| 每周 | `weekly_optimizer` / `bayesian_tuner` | 遗传算法 / 贝叶斯调参 |
| 每月 | `lifecycle` | 策略晋升 / 降级 / 退役（基于滚动表现） |
| 持续 | `factor_miner` / `factor_effectiveness` / `gray_deployer` | 因子挖掘、因子有效性评估、灰度部署 |

## 10. 回测与压力测试

- **回测**：`backtest/engine.py` 重放历史 K 线，走完整决策管道；`reporter.py` 生成 HTML/文本报告。
- **压力测试**（`backtest/stress_test.py`）：注入 3 种合成崩盘场景，评估熔断器保护效果：
  - 千股跌停（连续 3 天 -10%/日，跌停锁死）
  - 2015 股灾（10 天 -5.5%/日）
  - 2020 暴跌（5 天 -7%/日）
  - 对比「无熔断 vs 有熔断」的最大回撤。

启动命令：`python main.py --mode backtest --start 2023-01-01 --end 2025-12-31 --stress`

## 11. Web 面板

FastAPI 后端（端口 8501）+ 单页应用（ECharts 实时可视化，自动刷新，支持深色/浅色主题切换）。布局 = **常驻头部 + 6 个 Tab + 两个弹窗**，完整功能如下。

### 11.1 常驻区域（所有 Tab 均可见）

- **顶部栏**：系统标题「猎场系统 V7.0 Genesis」；**账户选择器**（全部账户 / 单个账户，切换后全局联动过滤）；**连接状态徽章**（连接中 / 运行中）；**手动刷新** 🔄；**设置** ⚙️。
- **Hero 大数字**：总资产（含涨跌 delta）、今日盈亏、累计盈亏。
- **KPI 磁贴**：持仓市值、可用现金、持仓数量、账户数、活跃信号。

### 11.2 Tab 1 — 总览

- **账户汇总卡片**：三账户（进攻型 / 稳定型 / 成长猎手）各自现金、持仓市值、总资产、盈亏，点击切换选中账户，卡片右上角 ✎ 可打开编辑弹窗。
- **收益曲线**：ECharts 折线，支持当日 / 周 / 月 / 年四档时间范围切换（组合快照数据）。
- **最新信号 + 最近交易**：并排两栏，展示最近买入信号与最近成交记录。
- **风控状态 + 资产配置**：并排两栏，熔断器当前状态与持仓/现金配置占比。

### 11.3 Tab 2 — 实时扫描

- **信号卡片**：最近一轮扫描产出的候选信号（代码、名称、评分、信号类型），按评分排序。
- **三账户决策网格**：每只信号在三个账户上的决策结果（买入 / 拒绝 / 跳过 + 十二层防线命中原因）。
- **扫描周期**：`market_scan` 每 60s 触发一次，面板展示最新一次扫描日志（`/api/v2/scan/log`），支持按账户过滤。

### 11.4 Tab 3 — 持仓交易

- **三账户持仓卡片**：按账户展示初始资金、总资产、持仓数量、当日/累计盈亏、持仓分配环图（股票 vs 现金）。
- **持仓明细表**：代码、名称、成本、现价、浮盈、仓位，支持按账户下拉筛选。
- **交易历史 + 执行日志**：并排两栏，成交明细与算法执行/拆单日志。

### 11.5 Tab 4 — 信号因子

- **策略筛选**：下拉切换「融合加权 / 动量 / 价值 / 突破」。
- **信号池**：融合后的股票信号（total_score、A/B/C 评级）。
- **因子库**：`factor_miner` 挖掘出的候选因子及定义。
- **因子有效性**：`FactorEffectivenessMonitor` 对各因子的 IC/胜率评估。
- **操作按钮**：🔬 触发因子挖掘、⚙ 触发参数优化（带 loading 反馈）。

### 11.6 Tab 5 — 风控进化

- **熔断器状态**：五层熔断实时触发状态、冷却倒计时、禁买名单。
- **策略生命周期**：策略晋升 / 降级 / 退役状态。
- **灰度部署**：`gray_deployer` 灰度发布进度与新旧策略对比。
- **复盘报告**：每日盘后复盘记录（`/api/v2/evolution/reviews`）。

### 11.7 Tab 6 — 行情分析

- **牛熊市判断**：每份报告头部展示当前市场状态徽章（🐂 牛市 / 🐻 熊市 / 🔄 震荡市 / ⚡ 震荡加剧 / 😱 极度恐慌 / 🔥 极度贪婪），由指数涨跌 + 市场广度规则法判定，与 `MacroLLM.analyze_market()` 的 `market_regime` 词汇对齐。
- **行情摘要 + 指数涨跌 chips + 涨跌家数/涨停/跌停**。
- **明日预测**：LLM（本地 Ollama 优先，DeepSeek 备选）生成的走势判断，LLM 不可用时回退规则引擎。
- **买卖推荐**：买入 / 卖出减仓两栏明细（含理由、浮盈亏）。
- **手动触发**：「立即生成收盘报告 / 生成午盘报告」按钮；盘后 15:00 与午盘 11:30 亦自动生成，最多保留 10 条。

### 11.8 账户编辑弹窗

从账户卡片 ✎ 打开，可编辑：账户名称、初始资金、总资产、可用现金、累计盈亏（金额/百分比）、账户状态（运行中 / 已暂停 / 已停止），保存后写回账户并刷新。

## 12. 调度与运行

`Scheduler` 是内置异步调度器（1 秒 tick），只在交易时段（9:30–11:30、13:00–15:00，且为交易日）运行 `trading_hours_only` 任务：

| 任务 | 间隔 | 说明 |
|---|---|---|
| `market_scan` | 60s | 主交易周期（信号→决策→订单） |
| `flash_scan` | 60s | 异动扫描 |
| `stop_loss_check` | 60s | 止损检查 |
| `risk_monitor` | 60s | 组合级熔断监控（L2-L5） |
| `data_sync` | 1200s | 数据同步 |
| `portfolio_snapshot` | 300s | 组合快照 |
| `daily_settlement` | 120s | 盘后结算（15:00-15:30） |
| `market_report` | 60s | 午盘/收盘行情报告 |
| `calendar_sync` | 86400s | 交易日历刷新 |

**启动方式**：

```bash
python main.py --mode v7        # 完整系统（多账户 + Web 面板）
python main.py --mode paper     # 单账户模拟盘
python main.py --mode web       # 仅 Web 面板
python main.py --mode backtest --start 2023-01-01 --end 2025-12-31
```

## 13. 技术特点

- **异步优先**：全 I/O 用 `async/await`，引擎单事件循环驱动。
- **事件驱动**：模块经 `EventBus.publish/subscribe` 通信，支持 `market.*` 通配符订阅。
- **懒加载**：数据源按需导入，缺依赖（tushare/akshare/torch）不阻塞启动。
- **SQLite 上下文管理器**：`db._get_conn()` 线程安全访问。
- **配置注入**：模块构造时注入 config 字典，无全局单例。
- **零重依赖**：当前运行环境仅 numpy/pandas/aiohttp，主数据源与交易日历均走免费 HTTP 接口。
